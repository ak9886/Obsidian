# Huffman Coding
When a message is sent, it should not be sent as plain text. It should be encrypted. If, for example 'a' is replaced with a '%' every time, then over time, the message could successfully be decrypted by threat actors. If the character 'a' is converted to its ASCII value, 65, it is a little better encrypted. Huffman Coding proposes a new system of encryption by using the frequencies of the letters as well. For example:
EXAMPLE: 'AABBC'
Unique Letters: 'ABC'
Frequencies:
- A : 2
- B : 2
- C : 1
With this set of frequencies of letters, we can get 2<sup>3</sup> combinations, so for example, we can put:
- A : 2 (2000)
- B : 2 (2001)
- C : 1 (1010)
# Huffman Tree
0# Huffman Tree

## 1. Definition

A Huffman Tree is a special type of binary tree used in Huffman Coding, a greedy algorithm for lossless data compression.

It assigns shorter binary codes to frequent characters and longer binary codes to less frequent characters. This minimizes the average number of bits required to represent each character.

---

## 2. Why Huffman Tree is Needed

In fixed-length encoding (such as ASCII), every character uses 8 bits.

In variable-length encoding (Huffman coding), frequent characters use fewer bits and rare characters use more bits. This reduces total storage and transmission size.

---

## 3. Properties of a Huffman Tree

1. It is a binary tree.
    
2. All actual characters are stored at leaf nodes.
    
3. Internal nodes store the sum of frequencies of their children.
    
4. It satisfies the prefix property: no code is the prefix of another code.
    
5. It produces optimal compression for known frequency distributions.
    

---

## 4. Algorithm to Construct Huffman Tree

Step-by-step procedure:

1. Count the frequency of each character in the input.
    
2. Create a leaf node for each character.
    
3. Insert all nodes into a min-heap (priority queue) based on frequency.
    
4. While more than one node remains in the heap:
    
    - Remove the two nodes with the smallest frequencies.
        
    - Create a new internal node with frequency equal to the sum of the two nodes.
        
    - Make the two removed nodes its left and right children.
        
    - Insert the new node back into the heap.
        
5. The final remaining node becomes the root of the Huffman Tree.
    

Time complexity (using a min-heap):  
O(n log n)

---

## 5. Example

Given string:

AABBC

Step 1: Frequency Table

Character | Frequency  
A | 2  
B | 2  
C | 1

Step 2: Build the Tree

Smallest frequencies: C(1) and A(2) → merge → 3  
Remaining: B(2) and 3 → merge → 5

Final tree:

```
        (5)
       /   \
     B(2)   (3)
            /   \
          C(1)  A(2)
```

---

## 6. Assign Binary Codes

Convention:  
Left edge = 0  
Right edge = 1

Tracing paths from root to leaf:

Character | Path | Code  
B | Left | 0  
C | Right → Left | 10  
A | Right → Right | 11

## 7. Encoding Process

Message: AABBC

A = 11  
A = 11  
B = 0  
B = 0  
C = 10

Encoded result:

11110010

Original ASCII size:  
5 × 8 = 40 bits

Huffman size:  
8 bits

Compression is achieved because frequent characters use shorter codes.

---

## 8. Prefix Property

A Huffman code is a prefix code.

Example codes:  
0  
10  
11

None of these codes is the prefix of another code. This ensures there is no ambiguity during decoding and allows immediate decoding without separators.

---

## 9. Decoding Using Huffman Tree

1. Start at the root.
    
2. Read bits one by one.
    
3. Move left for 0 and right for 1.
    
4. When a leaf node is reached, output the character.
    
5. Return to the root and continue.
    

---

## 10. Advantages

- Produces optimal prefix codes for known frequencies.
    
- Lossless compression.
    
- Efficient and widely used in compression formats.
    
- Based on a greedy strategy.
    

---

## 11. Limitations

- Requires frequency information to decode.
    
- Not very beneficial if all characters have equal frequency.
    
- Adds overhead for very small inputs.
    

---

## 12. Applications

- Text compression
    
- Image compression
    
- File archiving formats
    
- Data transmission systems
    

---

## 13. Important Exam Points

- Huffman coding is a greedy algorithm.
    
- It uses a min-heap for efficient construction.
    
- All characters appear at leaf nodes.
    
- Internal nodes store sum of frequencies.
    
- Time complexity is O(n log n).
    
- It guarantees optimal prefix codes for fixed frequency distributions.
    

---

## 14. Comparison with Fixed-Length Encoding

Feature | Fixed Length | Huffman  
Bits per character | Constant | Variable  
Compression | No | Yes  
Optimal for given frequency | No | Yes  
Prefix property | Not required | Required

---

## 15. Summary

A Huffman Tree minimizes the weighted path length of characters in a binary tree. By merging the least frequent symbols repeatedly, it produces optimal variable-length prefix codes and enables efficient lossless compression.
