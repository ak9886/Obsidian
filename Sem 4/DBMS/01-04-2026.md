## Answers
1) Transaction**  
A transaction is a sequence of database operations treated as a single logical unit of work.

**Properties (ACID):**

- **Atomicity:** All or nothing execution
- **Consistency:** Database remains valid before and after
- **Isolation:** Concurrent transactions don’t interfere
- **Durability:** Changes persist after commit

**States:**

- Active
- Partially Committed
- Committed
- Failed
- Aborted

**Examples:**

- Bank transfer (debit + credit)
- Online order placement
- Updating multiple related tables

---

2) Serializability**  
A correctness criterion ensuring concurrent schedules produce the same result as some serial execution.

**Schedule:**  
Order in which operations of transactions are executed

**Serial Schedule:**  
Transactions execute one after another without interleaving

---

3) Need for Concurrent Execution:**

- Improves throughput
- Better resource utilization (CPU, I/O)  
- Reduces waiting time
- Supports multi-user systems

---

4) Conflict Serializability:**  
A schedule is conflict-serializable if it can be transformed into a serial schedule by swapping non-conflicting operations (based on read/write conflicts).

---

5) View Serializability (New Serializability):**  
A schedule is view-serializable if it produces the same result as a serial schedule based on:

- Same initial read
- Same read-from relationships
- Same final writes
